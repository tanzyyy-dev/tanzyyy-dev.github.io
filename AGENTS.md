# Repository agent entry point

This is the Astro + TypeScript website for tanzyyy-dev. Keep this always-read file as a **skill router**, not a workflow manual.

## Select skills by task

- **Product/UI design** — page hierarchy, layout, styles, navigation, accessibility, or responsive behavior: read `.agents/skills/portal-design/SKILL.md`.
- **Astro development** — implementation, refactoring, tests, builds, or technical verification: read `.agents/skills/astro-development/SKILL.md`.
- **GitHub operations** — commits, pushes, pull requests, merges, or Pages deployment: read `.agents/skills/repository-operations/SKILL.md`.

Read the relevant skill(s) **before** doing that work; a task may require more than one. For documentation-only edits, read the affected documents and the GitHub operations skill if committing/pushing. Do not load unrelated skills.

## Documentation boundaries

- `AGENTS.md` contains only durable, repository-wide agent instructions and skill routing.
- `SKILL.md` files contain reusable, task-specific rules and procedures, not information about the current work session.
- `README.md` documents the project for readers: purpose, setup, usage, and enduring technical facts.
- **Never use `AGENTS.md`, any `SKILL.md`, or `README.md` as a status/situation memo, work log, handoff note, TODO tracker, migration plan, incident record, or AI response history.** Do not append progress reports, temporary blockers, unverified deployment states, or records of past fixes.
- Track time-bound plans and ongoing work in GitHub Issues or PRs; use commit history for completed changes. Update these documents only when the lasting instructions or project documentation themselves need to change.
