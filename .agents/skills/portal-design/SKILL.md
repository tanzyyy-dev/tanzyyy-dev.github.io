# Portal design guidelines

This skill guides **how to design**, not **what the finished screen must look like**. It is not a screen specification, a record of the current implementation, or a source of approved user requirements.

## Start from requirements and real content

- Use requirements agreed with the user as the design input. Do not treat existing UI, CSS values, or previous AI output as approved specifications.
- Understand who will use the interface and what they need to accomplish. Choose information hierarchy, navigation, and presentation to serve those tasks.
- If a missing requirement would change the intended outcome, clarify it before turning an assumption into a specification.
- Once requirements are agreed, make the necessary design decisions without asking approval for every detail. Incorporate user-directed revisions.

## Avoid AI Slop

- Reject generic, interchangeable AI-generated design: vague slogans, filler copy, decorative sections, gratuitous effects, and patterns added only to make a page seem polished.
- Do not invent projects, claims, statistics, testimonials, screenshots, or usable links.
- Do not duplicate content or introduce interface controls without a meaningful user purpose.
- Choose typography, spacing, color, imagery, motion, and components for their function and fit with the actual content. **No visual technique is prohibited merely by its appearance**; its use needs a reason.
- Prefer a coherent, distinctive result grounded in the product over fashionable template conventions.

## Design and review

- Inspect the existing interface and relevant content before proposing changes. Distinguish observed implementation from intended requirements.
- Consider desktop and mobile layouts, content hierarchy, readability, keyboard and touch use, accessibility, and Japanese/English presentation when relevant.
- Explain material design choices in terms of the requirements and their trade-offs, not because the current code happens to use particular values.
- Avoid unrelated visual or responsive changes during non-design tasks.
- Evaluate the outcome against the agreed requirements and actual user experience. Do not claim an interface has been visually checked without inspecting it.

Implementation, build, test, and deployment procedures belong to the corresponding task-specific skills.
